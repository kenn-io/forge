# Agent Hook Daemon Relay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route every Claude and Codex lifecycle hook through the authenticated Middleman daemon API, with daemon-owned activity transitions and Claude `SessionStart` context generated from persisted workspace metadata.

**Architecture:** The installed hook command carries only the Middleman config path. The CLI discovers and authenticates to the live daemon using the existing runtime metadata client, forwards the original JSON event and runtime-session header, and emits only the optional agent output returned by the daemon. A workspace API handler records every event through `agentactivity.Store`; Claude startup additionally resolves the matching workspace and calls the existing `BuildAgentContext`/`RenderAgentContext` pipeline.

**Tech Stack:** Go, Huma REST API, SQLite-backed workspace manager, file-backed daemon-owned activity store, `net/http`, Testify.

## Global Constraints

- The hook CLI is transport only: no direct activity-store writes, database access, or workspace-file reads.
- Every supported Claude and Codex lifecycle event is forwarded to the daemon.
- Hook delivery remains fail-open when daemon discovery, HTTP transport, or context generation fails.
- `CLAUDE.local.md` is never read by the hook or daemon endpoint.
- The existing `BuildAgentContext` and `RenderAgentContext` functions remain the sole workspace-context field mapping and renderer.
- Never bypass repository Git hooks.
